각 항목을 마칠 때마다 `[ ]` 를 `[x]` 로 바꾸며 진행합니다.
실행 주체가 **사람만 할 수 있는 일**(계정 발급·DNS·결제)은 「담당」에 표시했습니다.

## 0. 사전 결정 (PRD §13 확인 필요 사항)

- [ ] **Resend 발신 도메인** — DNS(SPF·DKIM) 설정이 가능한 도메인 확보. 담당: 사람
      대학 도메인 하위(`ai.gnu.ac.kr` 등) 또는 별도 도메인.
- [ ] **Supabase 플랜** — 6개월 운영이므로 Pro($25/월) 권장. Free 는 1주 비활동 시
      일시정지되고 백업이 없습니다. 담당: 사람
- [ ] **Vercel 플랜** — Hobby 는 비상업·개인 용도 조건. 대학 사업 적용 가능 여부 확인,
      불가 시 Pro 또는 대학 서버 Docker 배포. 담당: 사람
- [ ] **팀 계정 통제권** — 관리자 계정(gnuxai.ac.kr)으로 ChatGPT Team·Claude Team 콘솔에서
      좌석 발급·제거 권한이 있는지 확인. 좌석마다 고정 접속 링크를 확보.

## 1. Supabase 프로젝트

- [ ] 리전 `ap-northeast-2`(서울)로 프로젝트 생성. 담당: 사람
- [ ] SQL Editor 에서 `supabase/migrations/0001_init.sql` 전체 실행
      (또는 `psql "$DATABASE_URL" -f supabase/migrations/0001_init.sql`)
- [ ] 확인: `select count(*) from information_schema.tables where table_schema='public';` → 15 이상
- [ ] 확인: `select * from v_report_summary;` → 1행 반환
- [ ] Authentication > Providers > **Google** 활성화, OAuth 클라이언트 등록. 담당: 사람
- [ ] Authentication > URL Configuration > Redirect URLs 에 `<배포주소>/auth/callback` 추가
- [ ] Settings > API 에서 `Project URL`, `anon key`, `service_role key` 확보

## 2. 비밀 값 생성

```bash
openssl rand -hex 32      # APP_SECRET
openssl rand -hex 32      # CRON_SECRET
```

- [ ] 두 값을 안전한 곳(기관 비밀번호 관리소)에 보관.

## 3. Resend

- [ ] 도메인 추가 후 DNS 레코드(SPF·DKIM) 등록, 인증 완료. 담당: 사람
- [ ] API Key 발급 → `RESEND_API_KEY`
- [ ] 관리자 화면 「설정 > 발신 테스트 메일」로 수신 확인

## 4. Vercel 배포

- [ ] GitHub 저장소 `LimJeomseob/AI-Account-Concierge` 를 Vercel 프로젝트로 연결. 담당: 사람
- [ ] 환경변수 등록 (Production·Preview 모두)

| 이름 | 값 |
|---|---|
| `NEXT_PUBLIC_APP_URL` | 배포 주소 (예: `https://ai-account.vercel.app`) |
| `SUPABASE_URL` | Supabase Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key |
| `RESEND_API_KEY` | Resend API Key |
| `APP_SECRET` / `CRON_SECRET` | 2번에서 만든 값 |
| `INITIAL_ADMIN_EMAIL` | 최초 관리자 Google 계정 |

- [ ] 배포 후 `GET /api/health` → `{"ok":true,"db":"up"}` 확인
- [ ] `vercel.json` 의 Cron 2건이 Vercel 대시보드 > Cron Jobs 에 등록됐는지 확인
- [ ] Cron 수동 호출 확인
      `curl -H "Authorization: Bearer $CRON_SECRET" <배포주소>/api/cron/daily`

```bash
npx tsx scripts/import-accounts.ts accounts.csv   # 계정 100개
```

- [ ] `/admin` Google 로그인 성공 (허용 목록에 없는 계정은 「권한 없음」 확인 — T12)
- [ ] `설정` 에서 발신자·회신 주소·CORS 오리진·점검 메일 수신자 입력

- [ ] `계정` 에서 좌석마다 접속 링크 등록 → 대시보드 「접속링크 미등록」 0 확인

## 7. 시범 운영 (수용 기준 T1~T13)

**자동 검증** — 시범/스테이징 프로젝트에서:

```bash
ACCEPTANCE_CONFIRM=yes npm run test:acceptance
```

`lib/__tests__/acceptance.integration.test.ts` 가 T1~T13 을 순서대로 실행합니다.
테스트 데이터는 `ZTEST` 접두를 쓰고 종료 시 삭제하며, 실행 중 `RESEND_API_KEY` 를 비워
**실제 메일은 나가지 않습니다**(대기열까지만 확인).

**수동 확인** — 자동 검증이 덮지 못하는 항목:

- [ ] 실제 메일 수신 (계정명·접속 링크·인수 확인 링크·장애 신고 링크 포함)
- [ ] 인수 확인 링크 클릭 → 완료 페이지, 위조 링크 → 「링크가 올바르지 않습니다」 (T4)
- [ ] 관리자 일일 점검 메일 수신 (T5 의 「미인수 회수」 포함)
- [ ] 월간 스냅샷 메일 수신 (T9)
- [ ] Resend 일일 한도 초과분이 다음 날 재시도되는지 (T13)

**시범 프로그램 1개 + 테스트 계정 2~3개로 전 과정 1회 실행**

- [ ] 신청 → 승인 → 배정 → 메일 → 인수 → 종료 → 대화·메모리 삭제 → 팀에서 제거 → 회수 → 재배정

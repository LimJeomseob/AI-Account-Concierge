## 1. Supabase 프로젝트

- [ ] 리전 `ap-northeast-2`(서울)로 프로젝트 생성. 담당: 사람
- [ ] 마이그레이션을 **0001 → 0002 → 0003 순서로 모두** 적용. 0002·0003 은 enum `ADD VALUE` 때문에
      문장별 커밋이 필요하므로 SQL Editor 가 아니라 psql 로:
      `for f in supabase/migrations/000{1,2,3}_*.sql; do psql "$DATABASE_URL" -v ON_ERROR_STOP=1 < "$f"; done`
      (psql 이 없으면 `docker run --rm -i postgres:16 psql "$DATABASE_URL" -v ON_ERROR_STOP=1 < 파일`)
- [ ] 확인: `select count(*) from information_schema.tables where table_schema='public';` → 15 이상
- [ ] 확인: `select enum_range(null::program_status);` → `{시작전,진행중,완료}` (0002 적용됨)
- [ ] 확인: `account_secrets` 에 `access_url` 열이 있고 `password_enc` 가 없음 (0003 적용됨)
- [ ] 확인: `select * from v_report_summary;` → 1행 반환
- [ ] Authentication > Providers > **Google** 활성화, OAuth 클라이언트 등록. 담당: 사람
- [ ] Authentication > URL Configuration > **Site URL** 을 `<배포주소>` 로, **Redirect URLs** 에 `<배포주소>/auth/callback` 추가
      (누락 시 Google 로그인 뒤 인증 코드 없이 첫 화면으로 되돌아온다 — 로그인 화면에 `no_code` 안내가 뜬다)
- [ ] Settings > API 에서 `Project URL`, `anon key`, `service_role key` 확보

## 3. Gmail 발송

- [ ] 발신 Google 계정에서 **2단계 인증** 활성화. 담당: 사람
- [ ] 「Google 계정 → 보안 → 2단계 인증 → 앱 비밀번호」에서 16자리 앱 비밀번호 발급. 담당: 사람
      (Google 이 보여주는 띄어쓰기는 있어도 없어도 됨 — 코드가 공백을 제거함)
- [ ] 발신 계정 → `GMAIL_USER`, 앱 비밀번호 → `GMAIL_APP_PASSWORD`
- [ ] 일일 한도 확인: 개인 Gmail 약 500통/일(수신자 기준), Google Workspace 2,000통/일.
      한도 초과(5.4.5) 시 발송이 중단되고 다음 날 일일 작업에서 이어서 발송됨
- [ ] 설정 `from_email` 은 **쓰이지 않음** — From 은 Gmail 이 `GMAIL_USER` 로 고정. `from_name`·`reply_to` 만 설정
- [ ] 관리자 화면 「설정 > 발신 테스트 메일」로 수신 확인

## 7. 시범 운영 (수용 기준 T1~T13)

**자동 검증** — 시범/스테이징 프로젝트에서:

```bash
ACCEPTANCE_CONFIRM=yes ACCEPTANCE_DB_HOST=<시범프로젝트>.supabase.co npm run test:acceptance
```

`ACCEPTANCE_DB_HOST` 가 `SUPABASE_URL` 의 호스트와 다르면 테스트가 켜지지 않습니다 — 운영 DB 에서 실수로 돌리는 것을 막기 위한 장치입니다.
테스트는 자기가 만든 좌석·프로그램(`ZTEST…`) 안에서만 자동 배정하므로 운영 좌석·대기자를 건드리지 않습니다.

`lib/__tests__/acceptance.integration.test.ts` 가 T1~T13 을 순서대로 실행합니다.
테스트 데이터는 `ZTEST` 접두를 쓰고 종료 시 삭제하며, 실행 중 `GMAIL_APP_PASSWORD` 를 비워
**실제 메일은 나가지 않습니다**(대기열까지만 확인).

**수동 확인** — 자동 검증이 덮지 못하는 항목:

- [ ] 실제 메일 수신 (계정명·접속 링크·인수 확인 링크·장애 신고 링크 포함)
- [ ] 인수 확인 링크 클릭 → 완료 페이지, 위조 링크 → 「링크가 올바르지 않습니다」 (T4)
- [ ] 관리자 일일 점검 메일 수신 (T5 의 「미인수 회수」 포함)
- [ ] 월간 스냅샷 메일 수신 (T9)
- [ ] Gmail 일일 한도 초과(5.4.5) 시 발송이 중단되고 초과분이 다음 날 재시도되는지 (T13)

**시범 프로그램 1개 + 테스트 계정 2~3개로 전 과정 1회 실행**

- [ ] 신청 → 승인 → 배정 → 메일 → 인수 → 종료 → 대화·메모리 삭제 → 팀에서 제거 → 회수 → 재배정

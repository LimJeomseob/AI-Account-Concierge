### 7-3. 기술 부채·확인 사항

- Next.js 16 에서 `middleware.ts` 가 빌드 출력에 「Proxy (Middleware)」로 표시됨. 현재 빌드는 정상이나, Next 16 의 `proxy.ts` 명칭 전환 여부는 공식 문서로 확인 후 결정.
- E2E(Playwright) 테스트는 없음. 흐름 검증은 실 DB 통합 테스트로 대체 중.
- 통합 테스트는 `ACCEPTANCE_DB_HOST` 가 `SUPABASE_URL` 호스트와 같을 때만 실행되고, 자기 좌석·프로그램(SCOPE) 안에서만 배정한다(2026-10-28 운영 좌석 점유 사고 후 격리).
- 남은 보완 후보: 뷰의 anon 접근 차단(revoke), `mail_queue`·`logs` 보관 정책, Vercel `regions`, 시드 재실행 시 설정 덮어쓰기, 공개 신청 API 입력 길이 상한.

## 8. 주의사항

1. **0003 마이그레이션은 `password_enc`·`new_password_enc` 를 되돌릴 수 없이 삭제**한다. 구 데이터가 있는 DB 에 적용할 때는 사전 확인.
2. 브라우저 번들에 `SUPABASE_SERVICE_ROLE_KEY` 포함 금지. `'server-only'` import 를 지운 채 클라이언트에서 쓰지 말 것. 반대로 `scripts/` 에서 쓰는 모듈(`lib/settings-defaults.ts` 등)에는 `'server-only'` 를 넣지 말 것(커밋 `d2c1fa1` 원인).
3. 클라이언트 컴포넌트가 쓰는 상수·순수 데이터는 server-only 파일이 아닌 별도 파일에 둔다(예: `lib/transitions.ts`). 서버 컴포넌트가 `'use client'` 모듈의 상수를 import 하면 깨진다(커밋 `b7e0666`).
4. 접속 링크(`account_secrets.access_url`)·로그인 이메일은 **로그에 기록 금지**. 로그에는 actor·동작·ID 만.
5. 상태 변경은 반드시 `lib/state.ts` 경유. 계정을 정지·만료·가용으로 바꿀 때는 `current_assignment_id` 를 비워야 DB check(`accounts_current_assignment_status`)를 통과한다(이미 `transitionAccount` 에 반영, 커밋 `b969183`).
6. 메일 직접 발송 금지 — `lib/mail/queue.ts` 로 넣고 `dispatch.ts` 가 발송.
7. 날짜는 `todayKST()` 등 `lib/date.ts` 함수만. `new Date().toISOString().slice(0,10)` 금지.
8. 이메일은 소문자 정규화(DB 제약 `users_email_lower`).
9. 통합 테스트는 **운영 DB 에서 실행 금지**(실제 행을 쓰고 지움).
10. 커밋 메시지·주석에 규칙 번호(R1~R33)를 인용하고, 사양 변경 시 PRD 본문 + §18 변경 이력 + `CLAUDE.md` 대응표 + 운영매뉴얼을 함께 갱신하는 것이 지금까지의 관례.
11. Vercel Cron 은 UTC 기준(`0 0 * * *` = KST 09:00), Hobby 는 ±59분 오차.

## 1. 하루 일과

시스템이 매일 09:00(KST)에 자동으로 처리합니다. 관리자는 대시보드만 확인하면 됩니다.

| 자동 처리 | 내용 |
|---|---|
| 대여 종료 | 대여종료일이 지난 건을 회수중으로 전환 |
| 메일 발송 | 관리자 메일(점검·장애·스냅샷) 대기열 순차 발송. Gmail 한도·인증 오류 시 중단, 다음 날 재시도 |

관리자가 직접 해야 하는 일은 **승인 → 「승인 건 배정 + 메일 내려받기」 → 워크스페이스 초대**, **회수 처리(대화·메모리 삭제 → 팀에서 제거 → 회수 완료)**, **장애 대체** 세 가지입니다.
대시보드 상단에 빨간 경고(일일 작업 실패, 26시간 넘게 미실행, 메일 인증 실패)가 보이면 먼저 처리합니다.

## 2. 프로그램 등록 (학기 시작 전)

1. `관리자 > 프로그램` → 「하반기 24개 일괄 등록」 (최초 1회)
2. 「등록·수정」에서 **프로그램ID 드롭다운**으로 프로그램을 고르면 값이 채워집니다. **대여방식·기간·상한**을 고쳐 저장하세요.
   새 프로그램은 드롭다운을 「새 프로그램」에 둔 채 이름 등을 적어 저장하면 ID 가 자동으로 붙습니다.
   - 고정기간: 시작일~종료일 (참여자 전원 동일)
   - 배정일기준: 대여일수(days) — 배정된 날부터 개인별로 계산
3. 대여기간은 나중에 넣어도 됩니다. 「진행중」이면 기간이 없어도 접수는 열리며(신청 페이지에 「대여기간 추후 안내」로 표시), **기간을 넣기 전까지 자동 배정만 보류**됩니다. 목록의 대여기간 칸에 「미설정 — 배정 보류」로 표시됩니다.
4. **상태**는 목록의 드롭다운으로 바꿉니다(바꾸는 즉시 저장). 자동으로 바뀌지 않으므로 세 단계 모두 담당자가 직접 전환합니다.

| 상태 | 의미 | 신청 페이지 표시 |
|---|---|---|
| 시작전 | 등록만 된 상태(일괄 등록 직후 기본값) | 「접수 준비 중」, 선택 불가 |
| 진행중 | 접수 개시. 기간이 있으면 배정(내려받기) 대상 | 「접수중」, 선택 가능 |
| 완료 | 접수 종료. 새 신청·배정 없음 (기존 배정 회수는 계속 처리) | 「접수 종료」, 선택 불가 |

   접수를 열 때 「진행중」으로, 프로그램이 끝나면 **「완료」로 직접** 바꿔 주세요. 종료일이 지나도 자동으로 완료되지 않습니다.

## 3. 계정 등록

유료계정 현황(2026-10-29): **ChatGPT Business Standard 45개**, **Claude Team 71개**. 계약 수는 `설정`의
「계약 계정 수」에서 바꿀 수 있고, 대시보드 「유료계정 지원현황」이 계약 수와 등록 수를 비교해 보여 줍니다.

`관리자 > 계정 > CSV 가져오기`

```
계정번호,서비스,구분,로그인이메일,활성화일,만료일
GPT-001,GPT,운영,,2026-09-01,
CL-001,Claude,예비,,2026-09-01,
```

- **계정번호**는 GPT-001 … GPT-045, CL-001 … CL-071 처럼 서비스별 일련번호입니다.
- **구분**: 「운영」은 배정 대상, 「예비」는 장애 대체 전용입니다.
- 접속 링크는 쓰지 않습니다(2026-10-29 폐지). 배정된 신청자는 관리자가 팀 워크스페이스에 이메일로 초대합니다.
  예전 CSV 의 「계정ID」·「접속링크」 열은 그대로 넣어도 됩니다(접속링크는 무시).

### 3-1. 운영 DB 계정 수를 계약에 맞추기 (SQL, 2026-10-29)

마지막으로 받은 계정 목록 기준 ChatGPT 55개·Claude 54개 → 목표 ChatGPT 45개·Claude 71개.
Supabase 대시보드 → SQL Editor 에서 ① 확인 → ② 실행 → ③ 확인 순서로 진행합니다. **배정 중인 계정은 건드리지 않습니다.**

**① 현재 확인**
```sql
select service, status, count(*) from accounts group by 1, 2 order by 1, 2;
-- 줄일 ChatGPT 후보 (번호 46 이상)
select id, status, current_assignment_id from accounts
 where service = 'GPT' and substring(id from '\d+$')::int > 45 order by id;
```

**② 조정 실행** (한 트랜잭션)
```sql
begin;

-- Claude: CL-001 ~ CL-071 이 모두 있게 (없는 번호만 추가, 운영·가용)
insert into accounts (id, service, kind, status)
select 'CL-' || lpad(n::text, 3, '0'), 'Claude', '운영', '가용'
  from generate_series(1, 71) n
on conflict (id) do nothing;

-- ChatGPT: 번호 46 이상 중 가용·정지 계정을 만료로 (배정·회수중은 그대로)
update accounts
   set status = '만료', current_assignment_id = null, updated_at = now()
 where service = 'GPT'
   and substring(id from '\d+$')::int > 45
   and status in ('가용', '정지');

insert into logs (actor, action, target_id, detail)
values ('운영자(SQL)', 'account.contract_adjust', null, '{"gpt": 45, "claude": 71}');

commit;
```

**③ 결과 확인**
```sql
select service, count(*) filter (where status <> '만료') as 등록 from accounts group by 1;  -- GPT 45, Claude 71
-- 번호 46 이상인데 아직 배정·회수중이라 남은 ChatGPT 계정 (회수 완료 후 계정 화면에서 「만료」로 전환)
select id, status from accounts
 where service = 'GPT' and substring(id from '\d+$')::int > 45 and status in ('배정', '회수중');
```
대시보드 「유료계정 지원현황」에서 등록 수가 45·71 이면 끝입니다. 번호가 GPT-001 형식이 아닌 계정이 있으면 ①에서 먼저 확인하세요.

## 4. 승인 → 배정 + 메일 내려받기 → 초대 (매일)

`관리자 > 유료계정 사용현황` (구 「신청·배정」, 2026-10-29 개편)

- 위쪽: 서비스별 계정 현황(계약·사용중·회수중·가용·정지)
- 현황 조회: 「전체보기」와 상태별 버튼(건수 표시), 프로그램·플랫폼(ChatGPT·Claude)·이름·이메일·계정번호 조건(이름·이메일·계정번호는 부분 일치). CSV 내려받기·「승인 대기 일괄 배정」도 같은 조건을 씁니다
- 처리: 목록에서 「신청」 건을 골라 **「선택 승인 + 배정 + 이메일 내려받기」** → 승인과 동시에 계정이 배정되고 이름·이메일·계정번호 CSV 가 내려받아집니다. 가용 계정이 모자란 건은 「승인」으로 남고 CSV 에 「(대기)」로 표시됩니다
- 「승인만」: 배정 없이 승인만 합니다. 나중에 「승인 대기 일괄 배정」으로 배정합니다
- **사용현황 CSV 일괄 등록**(화면 맨 아래): 팀 워크스페이스에 직접 추가한 사람이나 지난 사용 이력을 CSV 로 올립니다.
  1. 「양식 내려받기」 또는 사용현황 CSV 내려받기 파일을 엑셀에서 고칩니다. 필수 열: 이름·이메일·플랫폼(ChatGPT·Claude). 선택 열: 프로그램(이름·번호)·계정번호·사용시작·사용종료(또는 사용기간 `2026-10-01~2026-12-31`)
  2. 등록 상태(「사용중」 또는 「회수완료」)와, CSV 에 프로그램이 비었을 때 쓸 기본 프로그램을 고릅니다
  3. 파일 선택 → **미리보기**(DB 변경 없음): 행마다 등록·건너뜀·오류와 배정될 계정번호가 보입니다
  4. **확정** → 「등록」 행만 처리합니다. 「사용중」은 계정번호가 비면 가용 계정을 번호 순으로 배정하고, 이미 사용중인 이메일·플랫폼은 건너뜁니다. 「회수완료」는 이력만 남기고 계정 상태는 바꾸지 않습니다
  - 처음 등록되는 사람의 구분(교원·직원 등)은 공란입니다(0007). 사용자 화면에서 고칩니다
  - 같은 프로그램에 한 사람이 Claude·ChatGPT 를 모두 쓸 수 있습니다(0008, 플랫폼별 1건). 「사용종료」가 비면 고정기간 프로그램의 종료일을 씁니다
- **사용현황 CSV 내려받기**(화면 오른쪽 위·조회 카드): 현재 조회 조건의 접수번호·프로그램·이름·이메일·소속·구분·플랫폼·계정번호·상태·희망·신청일·사용개시·대여기간을 내려받습니다(최대 5000건). 조회용이라 배정되지 않습니다

1. 상태 버튼 「신청」(필요하면 프로그램·플랫폼 조건도) → 목록에서 체크 → **「선택 승인 + 배정 + 이메일 내려받기」**.
   - 고른 건을 승인하고 **신청 순**으로 계정을 배정해(즉시 「사용중」) 고른 사람의 **이름·이메일·계정번호** CSV 를 내려받습니다.
   - 가용 계정이 모자라거나 배정상한에 걸린 건은 「승인」으로 남고 CSV 계정번호 칸에 「(대기)」로 나옵니다. 대여기간이 없는 프로그램은 배정하지 않습니다.
2. 「승인」으로 남은 건은 계정이 생긴 뒤 **「승인 대기 일괄 배정」** 으로 배정합니다(현재 조회 조건의 「승인」 건 대상).
3. 내려받은 이메일을 계정번호의 서비스(GPT-… → ChatGPT, CL-… → Claude) 팀 워크스페이스에 **초대**합니다.

- 자동 배정은 없습니다(승인 즉시·매일 09:00·회수 직후 모두 폐지, 2026-10-29). 배정은 위 버튼으로만 일어납니다.
- 「CSV 내려받기」·「이메일만 복사」는 조회용이라 배정되지 않습니다.
- 기존 유료계정 보유 여부는 배정 순서에 반영하지 않습니다.

## 5. 회수 (대여 종료 후)

대여가 끝나거나(자동), 관리자가 취소하거나, 목록에서 **「선택 회수 시작」** 을 누르면 「회수중」이 됩니다.

1. 유료계정 사용현황에서 상태 버튼 「회수중」을 누르거나, 회수할 「사용중」 건을 골라 **「선택 회수 시작」** 을 누릅니다.
2. 해당 계정의 **대화·메모리를 삭제**하고, 팀 콘솔(ChatGPT Team / Claude Team 관리자)에서 **그 사용자(멤버)를 팀에서 제거**합니다.
   (멤버 제거를 자동화하는 API 가 없어 이 단계는 수작업입니다.)
3. 완료 처리는 둘 중 하나로 합니다.
   - 행의 **관리** 칸에서 체크 ①「대화·메모리 삭제」·②「팀에서 제거」를 누른 뒤 그 건을 골라 「선택 회수 완료」
   - 여러 건을 골라 **「선택 회수 완료」** → 확인창에서 ①·②를 마쳤다고 확인하면 체크 2개를 표시하고 회수 완료
4. 회수 완료되면 계정이 가용으로 돌아갑니다. 대기자 배정은 「승인 대기 일괄 배정」으로 합니다(자동 재배정 없음).

> 2개 항목이 모두 체크되지 않으면 회수 완료 버튼이 오류를 냅니다.
> 회수 절차를 건너뛴 계정이 다음 사람에게 넘어가지 않도록 하는 안전장치입니다.

## 6. 장애 처리

참여자가 안내문의 「장애 신고」 링크로 신고하면 관리자에게 즉시 메일이 갑니다.
신고 링크는 배정이 「사용중」일 때만 받습니다(회수·취소된 옛 링크로는 신고 불가, 배정당 하루 5회).

1. `관리자 > 장애` 에서 건을 확인합니다. 유형이 「정지」면 계정 상태가 자동으로 정지가 됩니다.
2. 「대체 계정 배정」을 누르면 **예비 계정 우선**으로 같은 서비스의 계정이 배정되고,
   대여기간을 승계한 새 배정 건이 생성됩니다. 새 계정번호를 확인해 참여자를 워크스페이스에 다시 초대합니다.
   같은 장애를 두 번 대체할 수 없습니다(이미 처리된 장애는 거부).
3. 정지율은 장애 화면·실적에서 확인합니다(자동 경고 없음).

## 8. 개인정보

- 수집 항목·목적·보유기간은 `설정`에서 관리하며, 신청 페이지에 그대로 표시됩니다.
- 보유기간(기본: 사업 종료 후 1년)이 지나면 개인정보를 파기해야 합니다. **관리자 화면에는 파기 기능이 없습니다**(2026-10-28 제거, R30 개정).
  Supabase 대시보드 → SQL Editor 에서 아래 절차로 처리합니다. 실행 전 백업을 받아 두세요.
- 파기하면 이름·이메일·연락처가 「(파기)」로 바뀌고, 구분·소속·ID 는 실적 산출을 위해 남습니다.
  **실적 수치는 파기 후에도 변하지 않습니다**(실적은 사용자 ID 기준으로 셉니다).

**① 대상 확인** — 아직 파기하지 않은 사용자 수
```sql
select count(*) from users where purged_at is null;
```

**② 파기 실행** — 한 트랜잭션. 특정 사용자만 할 때는 각 `where` 에 `and id in ('U-0001', ...)` 를 덧붙입니다.
```sql
begin;

-- 신청 건의 이름·이메일 (이메일은 소문자 제약이 있어 사용자ID 기반 주소로 바꾼다)
update assignments a
   set name = '(파기)', email = lower(u.id) || '@purged.local', updated_at = now()
  from users u
 where u.id = a.user_id and u.purged_at is null;

-- 장애 신고의 신고자 이름·증상(자유 입력)
update incidents i
   set reporter = '(파기)', symptom = '(파기)'
  from assignments a join users u on u.id = a.user_id
 where a.id = i.assignment_id and u.purged_at is null;

-- 사용자
update users
   set name = '(파기)', email = lower(id) || '@purged.local', phone = null, purged_at = now()
 where purged_at is null;

-- 이미 보낸·실패한 메일 본문, 회수 알림(이름 포함)
update mail_queue set body_text = null, body_html = null where status in ('sent', 'failed');
delete from alerts;

-- 기록
insert into logs(actor, action, target_id, detail) values ('운영자(SQL)', 'privacy.purge_all', null, '{}');

```

## 9. 자주 겪는 상황

| 상황 | 대응 |

| 배정을 취소해야 함 | 「취소」 — 계정이 붙어 있으면 자동으로 회수중이 되고, 실적에서 빠집니다 |

| 메일이 계속 실패함 | 설정 > 「발신 테스트 메일」로 발송 테스트. 실패하면 `GMAIL_USER`·`GMAIL_APP_PASSWORD`(앱 비밀번호) 환경변수를 확인하고, 필요 시 Google 계정에서 앱 비밀번호를 다시 발급 |
| 계정이 회수중인데 재배정하고 싶음 | 체크리스트 2개를 완료하고 회수 완료 처리해야 가용이 됩니다 |
| 워크스페이스에 직접 추가한 사람(신청서 없음)을 반영해야 함 | 「기관관리자(Claude)」「기관관리자(ChatGPT)」 내부 프로그램에 「사용중」으로 등록합니다(0007, 공개 신청 목록에 안 보임). 구분은 공란이며 사용자 화면에서 고칠 수 있고, 대여 종료일이 없어 자동 종료되지 않으므로 회수는 직접 합니다 |
| 관리자를 추가해야 함 | 설정 > 로그인 허용 관리자 > 관리자 추가 (Google 로그인 이메일 기준). 등록된 계정은 로그인하면 바로 대시보드로 가고, 이미 「권한 없음」 화면에 있었다면 새로고침만 하면 재로그인 없이 대시보드로 이동합니다(2026-10-29). 「관리자 메일 수신자」 란은 메일 수신용이라 로그인 권한을 주지 않습니다 |

| 로그인 후 다시 로그인 화면이 나옴 | 접속한 주소 그대로 돌아오도록 고쳤습니다(2026-10-29). 계속되면 Supabase > Authentication > URL Configuration 의 Site URL 이 `https://ai-account-concierge.vercel.app`, Redirect URLs 에 `https://ai-account-concierge.vercel.app/auth/callback` 이 있는지 확인. 접속 주소는 이 하나로 고정돼 있고 다른 `*.vercel.app` 주소로 들어오면 자동으로 옮겨진다(2026-10-29) |

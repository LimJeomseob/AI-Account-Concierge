## 1. 하루 일과

시스템이 매일 09:00(KST)에 자동으로 처리합니다. 관리자는 대시보드만 확인하면 됩니다.

| 자동 처리 | 내용 |
|---|---|
| 대여 종료 | 대여종료일이 지난 건을 회수중으로 전환 |
| 자동 배정 | 승인 대기자에게 신청 순으로 좌석 배정 → 즉시 「사용중」(신청자 자동 메일 없음) |
| 메일 발송 | 관리자 메일(점검·장애·스냅샷) 대기열 순차 발송. Gmail 한도·인증 오류 시 중단, 다음 날 재시도 |
| 구독 만료 | 만료일이 지난 가용·정지 좌석을 만료 처리. **사용중·회수중 좌석은 만료하지 않고 경고만** |
| 점검 메일 | 관리자에게 오늘 할 일 요약 발송. 일일 작업 중 실패한 단계가 있으면 맨 위에 표시 |

관리자가 직접 해야 하는 일은 **승인 후 안내(「안내문 복사」로 접속 링크·장애 신고 링크 전달)**, **회수 처리(대화·메모리 삭제 → 팀에서 제거 → 회수 완료)**, **장애 대체** 세 가지입니다.
대시보드 상단에 빨간 경고(일일 작업 실패, 26시간 넘게 미실행, 메일 인증 실패)가 보이면 먼저 처리합니다.

## 2. 프로그램 등록 (학기 시작 전)

1. `관리자 > 프로그램` → 「하반기 24개 일괄 등록」 (최초 1회)
2. 「등록·수정」에서 **프로그램ID 드롭다운**으로 프로그램을 고르면 값이 채워집니다. **대여방식·기간·상한**을 고쳐 저장하세요.
   새 프로그램은 드롭다운을 「새 프로그램」에 둔 채 이름 등을 적어 저장하면 ID 가 자동으로 붙습니다.
   - 고정기간: 시작일~종료일 (참여자 전원 동일)
   - 배정일기준: 대여일수(days) — 배정된 날부터 개인별로 계산
3. 대여기간은 나중에 넣어도 됩니다. 「진행중」이면 기간이 없어도 접수는 열리며(신청 페이지에 「대여기간 추후 안내」로 표시), **기간을 넣기 전까지 자동 배정만 보류**됩니다. 목록의 대여기간 칸에 「미설정 — 배정 보류」로 표시됩니다.
4. **상태**는 목록의 드롭다운으로 바꿉니다(바꾸는 즉시 저장). 자동으로 바뀌지 않으므로 세 단계 모두 담당자가 직접 전환합니다.

| 상태 | 의미 | 신청 페이지 표시 |
|---|---|---|
| 시작전 | 등록만 된 상태(일괄 등록 직후 기본값) | 「접수 준비 중」, 선택 불가 |
| 진행중 | 접수 개시. 기간이 있으면 자동 배정까지 진행 | 「접수중」, 선택 가능 |
| 완료 | 접수 종료. 새 신청·자동 배정 없음 (기존 배정 회수는 계속 처리) | 「접수 종료」, 선택 불가 |

   접수를 열 때 「진행중」으로, 프로그램이 끝나면 **「완료」로 직접** 바꿔 주세요. 종료일이 지나도 자동으로 완료되지 않습니다.

## 3. 계정 등록

`관리자 > 계정 > CSV 가져오기`

```
계정ID,서비스,구분,로그인이메일,접속링크,활성화일,만료일
GPT-001,GPT,운영,gpt001@gnuxai.ac.kr,https://chatgpt.com/...,2026-09-01,2027-02-28
CL-001,Claude,예비,cl001@gnuxai.ac.kr,https://claude.ai/...,2026-09-01,2027-02-28
```

- **구분**: 「운영」은 자동 배정 대상, 「예비」는 장애 대체 전용입니다.
- **접속 링크**는 팀 콘솔(ChatGPT Team / Claude Team, 관리자 계정 gnuxai.ac.kr)에서 좌석마다 발급한
  고정 주소입니다. 배정되면 신청·배정 화면의 「안내문 복사」로 이 링크를 참여자에게 직접 전달합니다. 비밀번호는 다루지 않습니다.
- 링크가 없는 좌석은 **배정되지 않으며**, 대시보드 「접속링크 미등록」에 표시됩니다.
- 나중에 넣거나 바꿀 때는 `관리자 > 계정 > 접속 링크 등록·수정`에서 「링크 저장」을 누릅니다.

## 4. 승인 (매일)

`관리자 > 신청·배정` → 상태 「신청」 필터 → 체크 → **선택 승인**

- 설정의 「승인 즉시 배정」이 켜져 있으면 승인과 동시에 계정이 배정되고 안내 메일이 나갑니다.
- 가용 계정이 없으면 「승인」 상태로 대기하다가, 계정이 회수되는 즉시 자동 배정됩니다.
- 배정 순서는 **신청 순(applied_at)** 이며, 기존 유료계정 보유 여부는 반영하지 않습니다.
- 반려할 때는 사유를 입력하십시오. 사유는 비고에 남습니다.

## 5. 회수 (대여 종료 후)

대여가 끝나거나 관리자가 취소하면 계정이 「회수중」이 됩니다.

1. 대시보드 「회수 대상」 목록에서 계정과 로그인 이메일을 확인합니다.
2. 해당 좌석에 로그인해 **대화·메모리를 삭제**한 뒤, 신청·배정 화면에서 체크 ①「대화·메모리 삭제」를 누릅니다.
3. 팀 콘솔(ChatGPT Team / Claude Team 관리자, gnuxai.ac.kr)에서 **그 좌석을 팀에서 제거**해 접속을 차단한 뒤,
   체크 ②「팀에서 제거(접속 차단)」를 누릅니다.
   (좌석 제거를 자동화하는 API 가 없어 이 단계는 수작업입니다.)
4. 「회수 완료」를 누르면 계정이 가용으로 돌아가고 **대기자에게 즉시 재배정**됩니다.
   재배정된 참여자에게는 「안내문 복사」로 같은 접속 링크를 안내합니다.

> 2개 항목이 모두 체크되지 않으면 회수 완료 버튼이 오류를 냅니다.
> 회수 절차를 건너뛴 계정이 다음 사람에게 넘어가지 않도록 하는 안전장치입니다.

## 6. 장애 처리

참여자가 안내문의 「장애 신고」 링크로 신고하면 관리자에게 즉시 메일이 갑니다.
신고 링크는 배정이 「사용중」일 때만 받습니다(회수·취소된 옛 링크로는 신고 불가, 배정당 하루 5회).

1. `관리자 > 장애` 에서 건을 확인합니다. 유형이 「정지」면 계정 상태가 자동으로 정지가 됩니다.
2. 「대체 계정 배정」을 누르면 **예비 계정 우선**으로 같은 서비스의 계정이 배정되고,
   대여기간을 승계한 새 배정 건이 생성됩니다. 새 좌석의 안내문을 복사해 참여자에게 전달합니다.
   같은 장애를 두 번 대체할 수 없습니다(이미 처리된 장애는 거부).
3. 정지율이 설정값(기본 5%)을 넘으면 대시보드와 점검 메일에 「업체 협의 필요」 경고가 뜹니다.

## 7. 실적

`관리자 > 실적`

- 프로그램별·요약 CSV 를 언제든 내려받을 수 있습니다.
- 매월 1일 자동으로 스냅샷이 저장되고 관리자에게 메일이 갑니다. 「지금 생성」으로 수동 실행도 가능합니다.

## 8. 개인정보

- 수집 항목·목적·보유기간은 `설정`에서 관리하며, 신청 페이지에 그대로 표시됩니다.
- 보유기간(기본: 사업 종료 후 1년)이 지나면 개인정보를 파기해야 합니다. **관리자 화면에는 파기 기능이 없습니다**(2026-10-28 제거, R30 개정).
  Supabase 대시보드 → SQL Editor 에서 아래 절차로 처리합니다. 실행 전 백업을 받아 두세요.
- 파기하면 이름·이메일·연락처가 「(파기)」로 바뀌고, 구분·소속·ID 는 실적 산출을 위해 남습니다.
  **실적 수치는 파기 후에도 변하지 않습니다**(실적은 사용자 ID 기준으로 셉니다).

**① 대상 확인** — 아직 파기하지 않은 사용자 수
```sql
select count(*) from users where purged_at is null;
```

**② 파기 실행** — 한 트랜잭션. 특정 사용자만 할 때는 각 `where` 에 `and id in ('U-0001', ...)` 를 덧붙입니다.
```sql
begin;

-- 신청 건의 이름·이메일 (이메일은 소문자 제약이 있어 사용자ID 기반 주소로 바꾼다)
update assignments a
   set name = '(파기)', email = lower(u.id) || '@purged.local', updated_at = now()
  from users u
 where u.id = a.user_id and u.purged_at is null;

-- 장애 신고의 신고자 이름·증상(자유 입력)
update incidents i
   set reporter = '(파기)', symptom = '(파기)'
  from assignments a join users u on u.id = a.user_id
 where a.id = i.assignment_id and u.purged_at is null;

-- 사용자
update users
   set name = '(파기)', email = lower(id) || '@purged.local', phone = null, purged_at = now()
 where purged_at is null;

-- 이미 보낸·실패한 메일 본문, 회수 알림(이름 포함)
update mail_queue set body_text = null, body_html = null where status in ('sent', 'failed');
delete from alerts;

-- 기록
insert into logs(actor, action, target_id, detail) values ('운영자(SQL)', 'privacy.purge_all', null, '{}');

commit;
```
`alerts` 는 다음 일일 작업이 다시 만듭니다(이름은 「(파기)」로 표시).

**③ 확인** — 남은 개인정보가 없는지
```sql
select count(*) from users where purged_at is null;            -- 0
select count(*) from assignments where email not like '%@purged.local';  -- 0
```

## 9. 자주 겪는 상황

| 상황 | 대응 |
|---|---|
| 접속 링크를 못 받았다고 함 | 신청·배정 화면에서 해당 건 「안내문 복사」 후 다시 전달(자동 메일 없음) |
| 신청자 명단이 필요함 | 신청·배정 화면 필터 후 「CSV 내려받기」 또는 「이메일만 복사」 |
| 배정을 취소해야 함 | 「취소」 — 계정이 붙어 있으면 자동으로 회수중이 되고, 실적에서 빠집니다 |
| 계정 상태를 바꿀 수 없다고 나옴 | 「배정」·「회수중」은 시스템 상태라 직접 고를 수 없습니다. 회수중 좌석은 체크리스트로 회수 완료 |
| 메일이 계속 실패함 | 설정 > 「발신 테스트 메일」로 발송 테스트. 실패하면 `GMAIL_USER`·`GMAIL_APP_PASSWORD`(앱 비밀번호) 환경변수를 확인하고, 필요 시 Google 계정에서 앱 비밀번호를 다시 발급 |
| 계정이 회수중인데 재배정하고 싶음 | 체크리스트 2개를 완료하고 회수 완료 처리해야 가용이 됩니다 |
| 관리자를 추가해야 함 | 설정 > 관리자 추가 (Google 로그인 이메일 기준) |

## 10. 유의 사항 (Fact)

- OpenAI·Anthropic 소비자 약관은 계정 공유를 금지합니다. 본 시스템은 「1계정 1사용자, 순차 대여」
  원칙으로 설계되었으나, 약관 리스크는 사업 주체가 인지한 상태의 설계 전제입니다.
- ChatGPT Team·Claude Team 은 좌석 추가·제거를 자동화하는 공개 API 가 없습니다.
  시스템은 **안내·알림·체크·추적**만 담당하고, 팀 콘솔 작업(좌석 제거·접속 차단)은 관리자 수작업입니다.
- 윤리가이드라인 시청 여부는 기술적으로 검증하지 않습니다(영상 클릭 + 자기 확인으로 갈음).
